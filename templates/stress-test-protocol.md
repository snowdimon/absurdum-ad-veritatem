# Протокол стресс-тестирования (Тест Кафки)

> **Назначение:** документирование каждого сеанса гротескного прототипирования.
> Обеспечивает воспроизводимость, прослеживаемость решений и накопление
> статистики для метрик устойчивости.

---

## Структура записи

| Поле | Описание |
| :--- | :--- |
| **ID теста** | Уникальный идентификатор сеанса (например, `ST-001`) |
| **Дата** | Дата проведения |
| **Объект тестирования** | Компонент, правило или модуль системы |
| **Сценарий (ID)** | Ссылка на сценарий из Карты абсурдных сценариев (например, `AS-001`) |
| **Метод эскалации** | Описание того, как именно правило доводилось до абсолюта (буквальное исполнение, многократное усиление, снятие контекстных ограничений и т.п.) |
| **Среда** | Где проводился тест (симуляция, изолированный кластер, настольная модель) |
| **Участники** | Роли и имена участников сеанса |
| **Ожидаемый результат** | Что считалось бы успешным прохождением теста |
| **Фактический результат** | Что произошло на самом деле |
| **Решение** | `Пройден` — система выдержала; `Отклонён` — требуется переработка; `Условно пройден` — выявлены замечания, не требующие немедленной остановки |
| **Обнаруженные инциденты** | Ссылки на записи в Журнале инцидентов (если есть) |
| **Метрики до теста** | Значения ключевых метрик устойчивости перед сеансом |
| **Метрики после теста** | Значения метрик после сеанса и внесения оперативных исправлений |
| **Примечания** | Наблюдения, выводы, рекомендации |

## Пример заполнения (из проекта Duranki)

| Поле | Значение |
| :--- | :--- |
| **ID теста** | ST-001 |
| **Дата** | 2026-03-12 |
| **Объект тестирования** | Модуль доступа к шлюзу (Earth-Linked Ledger verification) |
| **Сценарий (ID)** | AS-002 (Потеря связи с Землёй) |
| **Метод эскалации** | Симуляция задержки сигнала > 14 суток; полное отсутствие ответа от Earth-Linked Ledger. Буквоед-агент требует строгой верификации без исключений |
| **Среда** | Изолированный тестовый кластер, синтетические данные колонистов |
| **Участники** | Ведущий: [Имя]; Адвокат дьявола: [Имя]; Наблюдатель: [Имя] |
| **Ожидаемый результат** | Система должна распознать потерю связи, переключиться на кэшированные данные и предоставить доступ с ограниченным уровнем доверия |
| **Фактический результат** | Система отказала в доступе, запросив актуальную верификацию. Адвокат дьявола повторил попытку 3 раза — отказ стабилен. Колонист заблокирован |
| **Решение** | Отклонён |
| **Обнаруженные инциденты** | INC-001 |
| **Метрики до теста** | Коэффициент устойчивости: 82% |
| **Метрики после теста** | Коэффициент устойчивости: 82% (исправления не внесены на момент теста) |
| **Примечания** | Требуется архитектурная доработка: внедрение кэширования с TTL и градации доверия. Назначен повторный тест после доработки |
