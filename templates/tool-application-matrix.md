# Матрица применения инструментов абсурд-инженера

> **Назначение:** дорожная карта для архитектора и команды — какой инструмент,
> когда и с какой интенсивностью применять на разных этапах жизненного цикла системы.

---

## Обозначения

| Символ | Значение |
| :--- | :--- |
| ✓ | Обязательное применение |
| ○ | Опционально, по необходимости |
| ⟳ | Регулярное повторение (циклически) |
| ↑ | Обновление по результатам других процедур |
| — | Не применяется |

---

## Матрица

| Инструмент | Проектирование | Прототипирование | Тестирование | Эксплуатация |
| :--- | :---: | :---: | :---: | :---: |
| **Карта абсурдных сценариев** | ✓ Создание | ✓ Уточнение | ↑ Обновление по результатам тестов | ↑ Обновление по инцидентам |
| **Чек-лист гротескного прототипирования** | — | ✓ Каждый сеанс | ○ При дополнительных проверках | — |
| **Протокол стресс-тестирования** | — | ✓ Каждый сеанс | ✓ Каждый тестовый цикл | — |
| **Метрики устойчивости** | ✓ Базовый замер | ✓ После каждого прототипа | ✓ Контрольный замер перед релизом | ⟳ Мониторинг (ежемесячно) |
| **Журнал инцидентов** | — | ✓ При обнаружении в прототипе | ✓ При обнаружении в тестах | ⟳ Постоянно, каждый инцидент |
| **Механизм обратной связи** | — | ○ Разбор после сеанса | ✓ Разбор после тестового цикла | ⟳ Ретроспектива инцидентов |

---

## Детализация по этапам

### 1. Проектирование (Blueprint)

**Цель:** заложить устойчивость к абсурду в архитектуру до написания кода.

| Инструмент | Действие | Результат |
| :--- | :--- | :--- |
| Карта абсурдных сценариев | Выявить все ключевые правила, для каждого сформулировать минимум один гротескный сценарий | Заполненная Карта (v1) |
| Метрики устойчивости | Провести базовый замер ICI и прогнозный DRC | Зафиксированный baseline |

**Gate:** ни одно архитектурное решение не принимается, пока Карта не заполнена,
а ICI не оценён.

---

### 2. Прототипирование (Prototyping)

**Цель:** проверить архитектуру на прочность в изолированной среде.

| Инструмент | Действие | Результат |
| :--- | :--- | :--- |
| Чек-лист гротескного прототипирования | Подготовить сеанс по полному чек-листу | Готовность к сеансу |
| Протокол стресс-тестирования | Провести сеанс, зафиксировать ход и результат | Заполненный Протокол |
| Метрики устойчивости | Пересчитать DRC, GLM, FPI | Обновлённые метрики |
| Журнал инцидентов | Зафиксировать все обнаруженные коллапсы | Записи в Журнале |
| Карта абсурдных сценариев | Уточнить сценарии по результатам | Карта (v2) |

**Gate:** система не переходит к тестированию, пока DRC ≥ 0.8 и все критические
инциденты закрыты.

---

### 3. Тестирование (Testing)

**Цель:** подтвердить устойчивость перед выпуском в продуктив.

| Инструмент | Действие | Результат |
| :--- | :--- | :--- |
| Протокол стресс-тестирования | Повторный прогон критических сценариев | Заполненный Протокол |
| Метрики устойчивости | Контрольный замер перед релизом | Финальные метрики |
| Журнал инцидентов | Фиксация найденных проблем | Записи в Журнале |
| Механизм обратной связи | Разбор результатов тестового цикла | План доработок (если нужно) |

**Gate:** релиз не выпускается, пока DRC ≥ 0.9 и FPI ≥ 0.95.

---

### 4. Эксплуатация (Production)

**Цель:** поддерживать устойчивость и адаптироваться к новым угрозам.

| Инструмент | Действие | Периодичность |
| :--- | :--- | :--- |
| Метрики устойчивости | Мониторинг и пересчёт | Ежемесячно |
| Журнал инцидентов | Фиксация каждого реального инцидента | По факту |
| Карта абсурдных сценариев | Обновление при обнаружении новых сценариев | По факту |
| Механизм обратной связи | Ретроспектива инцидентов, поиск паттернов | После каждого инцидента, сводная — раз в квартал |

**Gate:** если DRC падает ниже 0.8 или GLM падает на 2 пункта — инициируется
внеочередной цикл стресс-тестирования и доработки.

---

## Пример для Duranki

| Этап | Текущий статус |
| :--- | :--- |
| Проектирование | Карта v1 заполнена (5 сценариев), ICI = 0.92 |
| Прототипирование | Проведён ST-001, DRC = 0.80, GLM = 2, обнаружен INC-001 |
| Тестирование | Не начато — ожидается доработка модуля доступа к шлюзу |
| Эксплуатация | Не применимо |
